# 评测：从"我觉得它行"到"N 次跑下来 X%"

> 概念页，**不依赖某一个仓库**。具体到本项目的文件、行号、24 条任务的全表，看 [`evals/README.md`](../../evals/README.md)。
> 两个真实实例：`mini-agent/evals/`（判定看文本）和 `swe-agent/eval/`（判定看测试）。

## 0. 评测套件的五件套

任何 agent 评测都逃不掉这五件，缺一件就有一种失败方式。

| 部件 | 回答什么问题 | 缺了它 / 写坏了会怎样 |
|---|---|---|
| **任务** prompt | 我们要求它做什么 | 题目有歧义 → 两个都对，判据判一个 |
| **环境** fixture | 它做这件事时能看到的世界 | 环境里有捷径（答案在文件名里、上一次的答案还在盘上）→ 通过率虚高 |
| **判据** assertion | 什么样算做对了 | 判据松 → 永远 100%，零信息；判据紧 → 正确答案被判死 |
| **运行器** runner | 怎么跑 N 次、怎么隔离、怎么记账 | 前后互相污染 → "某条任务偶尔失败"，无法归因 |
| **归因** attribution | 这些样本哪些其实是一个样本 | 把 24 条当 24 个独立样本算方差 → 一个看起来严谨的假数字 |

一句话：**评测 = 判据自动化 + 样本独立性**。前者让机器替你跑，后者让你的数字有意义。

## 1. 判据只有两个可信来源

| 来源 | 什么时候用 | 例子 |
|---|---|---|
| **环境状态**（首选） | 能跑就跑 | 测试从红变绿（SWE 类）；文件内容真的被写入；API 真的返回了；数据库真的多了一行 |
| **文本**（退而求其次） | 任务本身没有可观测的环境变化 | "日志文件叫什么名字"这种纯问答 |

**为什么环境状态永远优先**：agent 说"我修好了"和"测试真的绿了"是两件事，前者只是文本。而最省事的通过方式往往是**改测试** —— 所以判定前必须先把被判定的东西还原。

用文本判时，**必须配一个输出契约**，否则判据会退化成"某个数出现过"：

> 反例：`all_of=("4140",)`。一个把两家报价都罗列、却**不下结论**的答案，因为它含 4140，判据就点头。它验证的是"这个数出现过"，不是"这个数就是答案"。
>
> 修法：题面统一要求最后一行写 `结论：<答案>`，断言只看那一行。被判的表面从"整段长答案"缩到"一行短结论"。

输出契约的额外好处：**"格式没按"和"答错"能分开报**。两者的修法完全不同（一个改 prompt，一个改 agent），混成一句"失败"，报告就只剩一个看不懂的百分比。

## 2. 被测对象有五个，模型只是其中一个

这是最容易被忽略的一条。**前四个坏掉时，报出来的通过率看起来完全正常。**

| 被测对象 | 它坏了的表现 |
|---|---|
| **fixture / 环境** | 题目本来就有两个答案；干扰项自我暴露；上次的产物还留在盘上被读到 |
| **任务集** | 断言漏写一条；fixture 路径写错；某条任务的产物恰好是另一条的 fixture |
| **判据** | 永远返回 True；只在自己的答案上通过；禁止了某些词而题面没禁止 |
| **隔离** | 模型能读到别的运行的轨迹 —— 泄漏**不会让通过率变低，只会让它变高**，所以没人会去查 |
| **模型** | 就是你要测的那个 |

推论：**判据本身也是代码，也要有测试。** 而且它比被测 agent 更该被测试 —— 因为判据错了，你花 N 倍的钱得到的是 0 信息，还要多花 N 倍的钱才能发现。

## 3. 每个对象的"最便宜探测器"

探测器要**便宜到随手就能跑**，否则不会有人跑。都是零 API 成本的。

| 对象 | 最便宜的探测器 | 判据 |
|---|---|---|
| fixture | 一段独立的 fixture 自检脚本 | 关键值唯一；干扰项不自我暴露；**数值两两不互为子串**（子串判据的正确性前提） |
| 任务集 | 结构不变量函数（被运行器第一段调用） | id/题面唯一；fixture 存在；产物 ∩ 环境 = ∅；必需串两两不互为子串；**无意义答案必须判失败** |
| 判据 | 拿**历史答案**离线跑一遍 | 结构不变量只有一条：`agent 宣告失败` 却 `判据通过` = 判据坏了。（反方向**不是** bug，是常态） |
| 隔离 | 静态白名单 + 证据扫描 + 端到端探针 | 先**校准**：证明扫描器看得见已知泄漏，再报"现在 0 处"。探针**没触发 = 失败**，不是通过 |
| 模型 | 交错跑 N 轮 + token 预算 | 外层轮次、内层任务，把"某半小时模型变慢"摊到所有任务上 |

两条最有价值的：

1. **"无意义答案必须判失败"** —— 一个连 `""` 或 `结论：不知道` 都判通过的断言，跑一万次也只会给你 100% 和零信息。**探针要能穿过所有前置解析**（比如结论行契约）**直达判定逻辑**，否则它会永远绿。
2. **"跨任务不许误命中"** —— 每条答案 × 每个断言，打一张矩阵。别的任务的断言在你的答案上通过，说明这些断言只能判断"某条任务的答案是否达标"，不能用来区分是哪条任务。

## 4. 四个反面模式

**a. 永远通过的断言。** 通过率 100% 且零信息。探测器：无意义答案必须判失败。

**b. 静默缩小样本。** 判据格式一改，老数据全部被判死，报告说"重叠 0 处 / 问题 0 个"—— **"零问题"和"样本是空的"在输出上长得一模一样**。
修法：**必须把被排除的条数打印出来**，并在可比样本不足一半时直接警告"矩阵不可信"。任何"我没发现问题"的结论，都要先回答"我看了多少条"。

**c. 判据与题面矛盾。** 断言禁止出现某些词，题面却没禁止 → 模型答对了，因为顺带补了一句解释就被判死。**答案对，解释被误判。**
修法不是删掉反例（那样更松），而是**让题面和断言一致**。

**d. 把 N 条任务当 N 个独立样本。** 任务 A 的答案必然包含任务 B 的答案时，它们是**一条事实**。
修法：给每条任务标一个"测的是哪一组独立事实"（fact），报告按 fact 归组。方差、置信区间在这一层算，不在任务条数上算。

## 5. 可复现的三条

| 规矩 | 为什么 |
|---|---|
| **原始结果永不覆盖** | 判据写错了，改完用 `--rejudge` 在同一批轨迹上重判，另存一份。**断言可以事后重跑，运行不能** —— 重跑等于为别人的 bug 付钱 |
| **结果必须记 git rev + 模型名 + 工具集** | 少了任何一个，那份通过率就不可横向比。"一份说不清给了什么工具的轨迹，事后没法归因" |
| **离线重判要说明它查不到什么** | 依赖环境的那半边（比如"文件真的被写入了"），事后环境早被清理了。**如实标出"未查"，不要假装查过** |

还有一条隐含的：**交错跑**（外层轮次、内层任务），而不是 `任务1×N → 任务2×N`。网络抖动、模型变慢、价格波动都会摊到所有任务上。

## 6. 两个实例对照

同一套部件，两种完全不同的判据实现。

| 部件 | `mini-agent/evals/`（阶段 1） | `swe-agent/eval/`（第二个 agent） |
|---|---|---|
| 任务 | 24 条 `Task`；判据是"结论行必须含哪些串" | 13 条 `Task`；判据是 **`f2p` 测试名集合** |
| 环境 | 11 个静态文本文件 | `fixtures/notes-app` + `tasks/Sxx/files` **注入 bug**（播种） |
| 判据 | 子串性质断言 `check(answer, root)` | **跑测试**：F2P 全绿 + 其余测试一条不挂（`eval/judge.py`） |
| 判据的失败面 | 文本判不了 → 加**结论行契约** | "改测试最容易通过" → **判定前先还原 `tests/`** |
| 题集自检 | fixture 10 项 + 结构不变量 9 类 | `eval/check_fixtures.py`：干净仓库全绿 / 每个种子**确实**把该任务的 F2P 弄红 / 种子**没有**弄红别的测试 |
| 运行器 | 交错、全局前置清理、`git rev`、`--plan/--replay/--rejudge` | 同一套（`run_swe.py` 开头明写"沿用 `evals/run_eval.py` 已验证过的四条规矩"）+ 每条运行重建沙箱副本 + patch 归档 |
| 离线重判 | `--rejudge`（只查文本） | `--rejudge`（判据的输入是仓库副本 + 答案 + patch） |

**这张表里最值得记的一行**是"判据的失败面"：判据换成什么形态，**失败面就跟着换**。
文本判据的失败面是"数出现过就算对"→ 需要输出契约；测试判据的失败面是"改测试就行"→ 需要判定前还原。
**设计判据时，先问"最省事的作弊方式是什么"，再堵它。**

`check_fixtures.py` 那三条也值得单独记：它证明的是"**题目真的会失败**"。题集里每条任务都得先证明"在干净环境上它是红的"，否则那条任务的通过率永远 100%，测不到任何东西。

## 7. 什么时候可以省

| 可以省 | 不能省 |
|---|---|
| 运行器（手工跑几条看看） | **"无意义答案必须判失败"** |
| 归因分组（任务少于 5 条且彼此无关时） | **"判据与题面一致"** |
| 特异性矩阵（任务间事实明显不同时） | **"原始结果不覆盖、判据可重判"**（一次也行） |
| 隔离审计（环境里根本没有别人的东西时） | **"环境状态优先于自述"** |

省掉的每一项，都要在写报告时明说"这一项我没测"。

## 8. 立项前的 10 问

1. 我的判据是**环境状态**还是**文本**？如果是文本，有输出契约吗？
2. 一个**空答案 / 无意义答案**能通过我的判据吗？
3. 我的断言会不会在**别的任务**的答案上通过？
4. 环境里有没有**捷径**（答案在文件名里、上次的产物还在盘上、上一次的轨迹可读）？
5. 哪条任务的答案**必然包含**另一条的？（→ 它们是一条事实）
6. 产物和环境（fixture）有重叠吗？
7. 改过题面之后，**老轨迹还能对得上号吗**？
8. 结果里有 `git rev` / 模型名 / 工具集吗？
9. 判据改了，我能不能**不重跑**就把旧数据重判？
10. 我的报告里，每个数字都能**指着一条命令**复现吗？
