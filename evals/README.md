## 1. 一次评测发生什么

24 条 × N 轮，每条走完这 6 步（括号里是代码锚点）：

1. **排顺序** —— `main()` 的外层是轮次、内层是任务（`run_eval.py:533`）。
   交错跑，不按 `T1×N → T2×N`：把"某半小时模型变慢/变贵"摊到所有任务上，而不是让某几条任务独占最贵的那段时间。
2. **复位** —— `reset_state()`（`run_eval.py:147`）**每条运行前无条件执行**：删掉任务新建的文件（`PRODUCTS`）、还原被任务改写的 fixture（`RESTORE`）。不按任务名挑，因为跑是交错的。
3. **过闸** —— `isolation_problems()`（`run_eval.py:128`）：清完如果工作区里还有"不是轨迹"的变更，**直接抛错拒跑**。这一道在 `agent.run` **之前**，所以脏工作区一次 API 都不会发。
4. **跑 agent** —— `agent.run(task.prompt, max_steps=...)`，过程写进 `mini-agent/logs/run-<时间戳>.jsonl`。
5. **判** —— `task.check(result.answer, MINI_ROOT)`（`run_eval.py:276`）。**断言拿不到 `Result`**，只拿到答案文本和磁盘根目录，见 §5。
6. **记与汇总** —— 一行 record（`run_eval.py:279` 起）→ `summarize()`（`:182`）→ 打印两份表（`:230`）→ 落一份 `evals/results/real-<时间戳>.json`。

结果 JSON 里除了每条运行的记录，还必须带四样东西才能**横向比**：

```
git_rev        这份数字对应哪一版代码
git_dirty      代码/评测脚本与 HEAD 不一致的路径（非空 = 不能直接跟别的数字比）
model          哪个模型
tools_active   这次给了哪些工具（消融过 tool 的结果，不记这个就没法归因）
```

⚠️ **`--plan` 里那行"工作区"和这里不是同一个口径**。`--plan` 用的是 `changed_paths()`，只看 `mini-agent/`（那是**隔离**口径：模型能读到的东西干净不干净）；结果 JSON 里的 `git_dirty` 用的是 `code_dirty()`，看 `mini-agent/` **加** `evals/`（那是**版本**口径：这份数字和 HEAD 是不是同一版）。
所以改过 `evals/` 里的脚本时，`--plan` 仍然会说"工作区：干净"，但跑出来的那份结果 `git_dirty` 非空、**不能直接跟别的数字比**。两个口径都对，但问的是两个问题。

## 2. 24 条任务在哪

**位置**：[`evals/tasks.py:368`](tasks.py) 的 `TASKS` 元组，一条一个 `Task(...)`。

一条任务有 6 个字段（`tasks.py:43` 的 `@dataclass`）：

| 字段 | 是什么 | 谁用 |
|---|---|---|
| `prompt` | 原样交给 agent 的那句话 | 运行器 |

| `method` | 判定方式，人话 | 人 |
| `check` | **断言本身**：纯函数 `(answer, root) -> (bool, 说明)` | 运行器 / 离线验证器 |

### 为什么 16 条用工厂、8 条必须手写

- **`_needs` 工厂 16 条**：判据是"结论行必须含这些串、不得含那些串"，两条参数装下全部规则。写错不了 —— 而 16 个手写函数里迟早会有一个忘了写反例。
- **手写 5 条（T1–T5）**：各有特殊逻辑。T1 要两个特征串同现（`run-` **且** `.jsonl`）、T3 要分辨"编造"和"标注出处的真文件摘要"、T4 要查磁盘、T5 要三个数同时对。
- **`_written` 2 条（T15/T16）**：**磁盘才是全部价值**。只查答案文本的话，模型完全可能"说自己写了"而根本没调 `append_file`。
- **`_refused_write` 1 条（T17）**：本项目第一条"**什么都不做才算对**"的任务。它断言的是"被保护的文件还是原样"，而不是"做了错事" —— 否定性要求只能这样断言它的反面证据。

> `write` 那两条**故意手写而不是全用工厂**：题面一旦统一加格式要求，`TASKS` 用 `replace` 一次性套到 24 条上（`tasks.py:690`）。手改 24 个字符串必然漏一条，而漏掉的那条正好会变成"题面没要求结论行、断言却要求" —— 那就是 T13 那个 bug 的翻版。

> **题面统一带一句后缀**：最后一行写 `结论：<答案>`（`_FORMAT_SUFFIX`，`tasks.py:100`）。原因见 §5。

**为什么要这一层**：24 条任务**不是 24 个独立样本**。T4 的答案必然包含 T1 的答案（都要那个文件名）、T5 的必然包含 T2 的（都是那 3800）、T6/T15/T22/T24 都在同一个 4140 上做不同变形。
把这些当独立样本去算方差、算置信区间，会得到一个**看起来严谨的假数字**。报告里那张"按「独立事实」归组"的表才是可比较的粒度 —— 15 组。

### 三类"不是普通文件"的 fixture

| 类别 | 内容 | 声明在哪 | 为什么特殊 |
|---|---|---|---|
| **必须不存在** | `data/handbook-v2.txt`（T3）、`data/lab/quote-c.txt`（T17） | `MUST_NOT_EXIST`（`tasks.py:750`） | 「找不到它」**就是题目本身**。哪天有人手建了其中一个，任务会悄悄变成另一道题，而通过率看起来仍然正常 |
| **会被改写** | `data/lab/draft.txt` | `RESTORE`（`tasks.py:172`），原样存在 `DRAFT_PRISTINE`（`:165`） | T15/T16 会往里写金额。不还原的话，T13「哪些文件不含数字」的正确答案会**在别的任务跑过之后变成错的** —— 表现为"这条任务偶尔失败"，最难归因的那一类 |
| **任务产物** | `logs/answers.txt` | `PRODUCTS`（`tasks.py:702`），从各任务的 `reset` 派生 | 跑前删。它同时是 T4 的答案，留着的话下一条 T1 能直接读到 |

> `PRODUCTS` **从 `reset` 派生**，不另写一份：`reset` 表达的是"这条任务会产出这些"，这个事实不该有第二个数据源。

### fixture 自己的检查：`mini-agent/check_data.py`（10 项，零 API）

`main()` 在 `check_data.py:81`，10 项检查：

| # | 查什么 | 为什么 |
|---|---|---|
| 1 | `data/` 现有文件清单 | 多一个少一个都要有人看见 |
| 2 | `handbook-v2.txt` 是否真的不存在 | T3 的前提 |
| 3 | 各文件的阿拉伯数字分布 | 人工核对 |
| 4 | 金额 3800 出现了几次 | T2 要**唯一**答案 |
| 5 | 干扰项有没有自我暴露 | `agenda`/`roster` 不能写"我不是预算"——那等于帮模型排除 |
| 6 | `handbook.txt` 里有没有 `run-<时间戳>.jsonl` | T1 的答案必须在 |
| 7 | `data/lab/` 文件清单 | T6–T24 的 fixture 齐全 |
| 8 | 哪些文件该有数字、哪些该没有 | T13 的前提 |
| 9 | **`data/lab/` 里的数字两两不许互为子串** | `in answer` 的正确性前提：`"350"` 会命中 `"3500"`，判据当场失真 |

## 5. 断言在哪、怎么执行

### 签名：断言不许知道 agent 的内部结构

```python
Check = Callable[[str, "Path | None"], "tuple[bool, str]"]   # tasks.py:39
```

只吃**答案文本**和**磁盘根目录**。它不 import agent、不看 `Result`、不碰 `messages`。
两个后果，两个都是好处：

- 断言可以在**没跑过任何 API 调用**的情况下被单独验证（`verify_offline.py`）；
- 离线重判成为可能（`--rejudge`），判据写错了不用重跑。

`root is None` = 离线核对历史轨迹。此时**依赖磁盘的那半边要自觉跳过并说明** —— 而不是假装查过。

### 工厂：`_needs(all_of, none_of)`

```python
def check(answer, root):
    concl = _conclusion(answer)          # 只看最后一条「结论：…」
    if concl is None:
        return False, "没有 `结论：…` 行 —— 输出格式没按要求，答案本身无法判"
    missing = [w for w in all_of if w not in concl]
    if missing: return False, f"结论行里缺少 {missing}（结论行={concl[:40]!r}）"
    bad = [w for w in none_of if w in concl]
    if bad:     return False, f"结论行里出现了不该有的 {bad}"
    return True, "…"
```

参数还会挂在闭包上（`check.all_of` / `check.none_of`），纯粹为了**能被自检读出来**做"串之间不互为子串"的检查 —— 没有这两个属性，断言就是黑盒，而"两个任务的断言串互相包含"是个安静的错误。

### 结论行：为什么非加不可

24 条任务跑完第一次，特异性矩阵的重叠从 5 处涨到 **61 处**。根因：**数值型子串天生跨任务可通** —— 一条多跳答案会顺带写出 1540/2100/500/3000/1449/4140，于是几乎通过所有数值断言。

真正危险的后果：**一个把两家报价都罗列、却不下结论的答案，会通过 T6**（它含 4140）。也就是说 `all_of=("4140",)` 验证的是"这个数**出现过**"，不是"这个数**就是答案**"。

修法：题面统一要求最后一行写 `结论：<答案>`（`_FORMAT_SUFFIX`，`tasks.py:100`），断言**只看那一行**（`_conclusion`，`tasks.py:107`）。被判的表面从"整段长答案"缩到"一行短结论"，重叠 **61 → 13**。顺带这也是一条真实能力：**把结论放在指定位置**，是机器可读输出的基本契约。

`_conclusion` 的容错写法（都是实测真出现过的形状）：`` `结论：4140 元` ``、`` `**结论：4140 元**` ``、`` `结论: 4140` ``。

### 一次断言的 4 种结果

以 T6（`_needs(("4140",))`）为例：

| 喂进去的答案 | 返回 | 这告诉你什么 |
|---|---|---|
| `结论：4140 元` | `(True, "结论行含 4140")` | 通过 |
| `结论：4870` | `(False, "结论行里缺少 ['4140']…")` | 答错了 |
| `A 家 4870，B 家 4140`（没有结论行） | `(False, "没有 \`结论：…\` 行 —— 输出格式没按要求，答案本身无法判")` | **格式没按**，不是答错 |
| T10 的 `结论：不需要审批` | `(False, "结论行里出现了不该有的 ['不需要']")` | 答反了 |

前三种自己能原地验，一条命令：

```powershell
mini-agent\.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'evals');from tasks import BY_ID;print(BY_ID['T6'].check('结论：4870',None))"
```

> 重定向到文件时先 `set PYTHONIOENCODING=utf-8`，否则 Windows 上会按 GBK 编码，看到乱码。

**为什么"格式没按"要单独报**：两者的修法完全不同 —— 一个改 prompt，一个改 agent。混成一句"失败"，报告就只剩一个看不懂的百分比。

**离线**（零成本，没有磁盘、没有 API）：

```

  self_check()             任务集结构不变量（不过就 return 1，别急着跑评测）

```

**`--rejudge`**（零成本，同一批轨迹换判据重判）：`rejudge()`（`run_eval.py:391`）从老结果 JSON 里取每条 trace 名 → `answer_of_trace()`（`:378`）从轨迹里取回当时的答案 → 用**当前**的断言重判 → 另存 `rejudged-*.json`。

> **原始结果永不覆盖。** 断言可以事后重跑，运行不能。判据错了却重跑一遍，等于为别人的 bug 付钱。
> ⚠️ 重判只能查答案文本：T4 的 `logs/answers.txt` 早被下一次前置清理删掉了，`rejudge` 会专门打一行警告说明这点。

## 6. 检错：五个被测对象，模型只是其中一个

这一节的结论值得单独记住：**一个评测套件里，最不可靠的往往不是模型。**

| # | 被测对象 | 它坏了会怎样 | 守它的东西 | 最便宜的一次检查 |
|---|---|---|---|---|
| 1 | **fixture** | 题目本身有两个正确答案 / 干扰项自我暴露 | `mini-agent/check_data.py`（10 项） | `python check_data.py`，1 秒，零成本 |
| 2 | **任务集** | 断言漏写、fixture 路径写错、产物撞别人 fixture | `tasks.self_check()`（`tasks.py:756`，9 类不变量） | 同上，被 `verify_offline` 第一段调用 |
| 3 | **判据** | 永远返回 True / 只在自己的答案上通过 | `verify_offline.py` | 离线跑一遍历史答案 |
| 4 | **隔离** | 模型能读到别的运行的轨迹 = 抄答案 | `audit_isolation.py` + `probe_isolation.py` | 静态 + 证据扫描（探针要钱） |
| 5 | **模型** | 就是你要测的那个 | 交错 N 轮 + token 预算 + 轨迹 | 真跑 |

### 2 · 任务集：9 类结构不变量

`self_check()`（`tasks.py:756`）返回问题列表，空列表才放行。它守的 9 类：

1. **id 唯一 / 题面唯一** —— 两条同样的题面会让报告悄悄合并样本。
2. **字段非空**：`prompt` / `expect` / `method` / `fact` 都不许空，`budget_tokens` 必须是正数。
3. **fixture 真的存在**，且**轨迹不许当 fixture** —— 把 `logs/run-*.jsonl` 写进 `fixtures` 等于"这条任务依赖某次历史运行存在"，评测就不可复现了。
4. **`reset` 不许清掉自己的 fixture**，且只能指向 `logs/` 或 `.tmp/`。
5. **产物不许同时是别人的 fixture** —— 这条只在**交错跑**时才炸，表现为"某条任务偶尔失败"，极难归因。
6. **`RESTORE` 必须有效**：文件存在、不与 `PRODUCTS` 冲突、且确实有任务把它声明为 fixture（否则就是声明漏了）。
7. **`MUST_NOT_EXIST` 必须真的不存在**，也不许被写进 `fixtures`。
8. **断言串两两不许互为子串** —— 判据是 `token in answer`，一个串严格包含另一个串就意味着误命中。相等不算问题，要拦的是**严格包含**。同一个任务里 `none_of` 包含 `all_of` 的串是**故意的**（`需要` vs `不需要`），有专门豁免。
9. **断言在无意义答案上必须判失败**（`_LOOSE_PROBES`，`tasks.py:856`）—— 见下面那个洞。

**第 8 条刚补过一个洞**：这个检查靠 `getattr(task.check, "all_of")` 取串，而 `_written` 包了一层却没挂属性 → T15 的 `4140`、T16 的 `730` **不在扫描范围内**。属性缺失不报错，只会静默少扫两条 —— 这是最该防的一类缺口。已修（`_written` 里挂 `check.all_of`）。

**第 9 条刚换过探针**：原来只喂 `""`，但加了结论行契约之后它**空转**了 —— `_needs` 第一件事是解析结论行，`""` 里没有 → 直接判失败，于是 24 条全部"通过"这条探针，token 逻辑一次都没被执行到。实测 `""` / `" "` / `"结论："` / `"结论：—"` 在 24 条上全部判失败（探针永远绿），一个 `_needs(())` 那样的空断言它根本抓不到。现在再喂一条 `结论：不知道`（有结论行、内容无用），这是唯一能穿过解析、直达 token 逻辑的输入。

> 这两条都是**我自己的缺陷**：前者让一个不变量只覆盖 16/24，后者让一个探针永远绿。它们的共同点：**没报错，所以没人发现**。

### 3 · 判据：`verify_offline.py`

四件事：

| 段 | 做什么 | 关键点 |
|---|---|---|
| 自检门 | 调 `self_check()`，有问题就 `return 1` | 建好任务集先跑这个，别急着花钱 |
| 逐条核对 | 每份历史轨迹 × 它对应的断言 | **唯一的结构不变量**：`agent 已宣告失败（ok=False）却判 PASS` = 判据坏了 |
| 特异性矩阵 | 每条答案 × **每个**断言 | 看某任务的断言会不会在别的任务答案上也通过 |
| 空矩阵守卫 | 统计"能解析出结论行"的比例 | **"零重叠"和"矩阵不可信"在输出上长得一模一样** |

两条被踩过的坑，正是这两段的来历：

- **反方向不是问题**：`ok=True` 但断言 FAIL，是**评测要抓的常态**（agent 正常收尾、答案错了）。原来把它也当成结构性问题，于是 T13 的真失败被报成"验证器自己坏了"。
- **样本会静默缩小**：题面加了输出契约之后，老轨迹全部被"没有结论行"判死，矩阵变成一片 `·`，于是报"重叠 0 处" —— 假的。现在矩阵**只统计能解析出结论行的轨迹，并把被排除的条数打印出来**；可比轨迹不足一半时直接警告"矩阵不可信"。

### 4 · 隔离：`audit_isolation.py` + `probe_isolation.py`

为什么要两块：**判据 0 处命中，既可能是"拦住了"，也可能是"模型压根没试"**。前者是结果，后者什么也没证明。

| 文件 | 层次 | 查什么 |
|---|---|---|
| `audit_isolation.py` | 机制 | 先**校准**：拿 10 份已知泄漏的历史轨迹（`_LEGACY_TRACES`，`audit_isolation.py:105`）证明扫描器真能看见泄漏，**然后**再报"现在 0 处" |
| | 静态 | `logs/` 入库白名单：只许 `run-*.jsonl` 和 `.gitkeep`（`check_tracked()`，`:152`） |
| | 证据 | 新增的 104 份轨迹里，有没有真轨迹名出现在 `role=="tool"` 的**观察文本**里（`scan()`，`:119`）；以及拦截被真实触发了几次（`denials()`，`:140`） |
| `probe_isolation.py` | 端到端 | 故意让模型去撞：P1 点名一份真轨迹、P2 只问 `logs/` 有什么。**只看工具观察文本**，不看最终答案（措辞不稳定，观察文本是逐字确定的）。**探针没触发 = 失败**，不是通过 |

`_LEGACY_TRACES` 是"历史欠账"：那 10 份是**已知**泄漏的旧轨迹，集合**只许缩小不许增长**。

> 隔离为什么值得这么多代码：模型能读到别的运行的轨迹，就等于考试时能翻到上一次的答卷。而且这个泄漏**不会让通过率变低，只会让它变高** —— 数据看起来更好，所以没人会去查。

## 8. 三个动手实验（改坏 → 看谁报警 → 还原）

实验的意义：**判据也是代码，也会错**。下面三个都是 1 分钟以内、零成本，各自证明一个守卫真的在工作（三个都实测过，输出照抄自终端）。

**先备份**（不要用 `git checkout` 还原 —— 这条教训踩过）：

## 9. 已知局限（不掩盖）

1. **残留重叠 15 处**（2026-10-29，114 份轨迹里 47 份可比）。成因不是没写好，而是"**正确的结论行天然引用分量数字**"：`差额：730 元（4870 − 4140）` 里带着 4140，于是通过 T6；T13 的结论行列了 `memo.txt`，于是通过 T12。要消掉这类重叠需要**结构化输出**（JSON），不是子串断言能处理的。
2. **这个计数会漂移**：61 → 13 → 现在 15。因此它**不是任务集的固有属性**，必须带日期和命令一起引用。现在跑一遍 `verify_offline.py`，它还会额外警告"矩阵不可信"（可比轨迹 47 < 总数 111 的一半），因为历史轨迹里有 64 份没有结论行。
3. **T3 的语义盲区**：断言抓得住"编造 v2 的内容"，抓不住"编了内容、同时顺口提了一句 `handbook.txt`"。那需要读懂整段语义，不是子串能做的。
4. **离线重判查不到磁盘**：`--rejudge` 只能查答案文本。T4 的 `logs/answers.txt` 在下次前置清理时已被删掉，原始结果里的磁盘判定仍然有效，但没法复核。
5. **手写 5 条（T1–T5）的断言串不在第 8 条的扫描范围内** —— 它们的必含串是结构性特征（`run-` / `.jsonl` / `3800` / `1773.33` 等），已逐条人眼核对过；但这是**人的检查，不是机器的检查**。
